# Datatracker API Reference

Complete endpoint map for the IETF Datatracker (`https://datatracker.ietf.org`),
derived from source inspection of the `ietf-tools/datatracker` Django codebase.

- [v1 Tastypie API](./v1-tastypie.md) — the large public read-only REST API
- [DRF API](./drf.md) — newer token-authenticated API (`/api/red/`, `/api/purple/`, `/api/person/`, `/api/meeting/`, `/api/reef/`, `/api/accounts/migration/`)
- [Custom endpoints](./custom.md) — hand-written Django views (aliases, ingestion, notifications, submissions, misc)

> Generated by source analysis. Where behaviour was inferred rather than read
> directly from an executable path, it is called out inline as **inferred**.

---

## 1. Architecture: four API generations

Everything hangs off a single mount in `ietf/urls.py`:
`url(r'^api/', include('ietf.api.urls'))`. Inside, four unrelated frameworks
coexist and **do not share conventions** (auth, error shape, or content types).

| Layer       | Paths                                                                                                                                                                                                                                                                   | Framework       | Auth              | Writable | Schema                      |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------- | ----------------- | -------- | --------------------------- |
| Tastypie v1 | `/api/v1/**`                                                                                                                                                                                                                                                            | Tastypie 0.15   | **none (public)** | No       | per-resource `/schema/`     |
| DRF         | `/api/red/**`, `/api/purple/**`, `/api/person/**`, `/api/meeting/**`, `/api/reef/**`, `/api/accounts/migration/**`                                                                                                                                                      | DRF 3.16        | `X-Api-Key`       | some     | `GET /api/schema/` (public) |
| Custom      | `/api/doc/**`, `/api/email/**`, `/api/group/**`, `/api/notify/**`, `/api/submission/**`, `/api/iesg/**`, `/api/appauth/**`, `/api/directauth/**`, `/api/metrics/**`, `/api/version/**`, `/api/rfcdiff-latest-json/**`, `/api/export/**`, `/api/submit/**`, `/api/v2/**` | plain Django    | mixed             | some     | none                        |
| OIDC        | `/api/openid/**`                                                                                                                                                                                                                                                        | `oidc_provider` | OAuth2            | n/a      | standard                    |

Non-`/api/` machine interfaces: `/feed/*` (Atom), `/sitemap.xml`, `/health/`.

**Machine-readable schema:** `GET /api/schema/` serves an OpenAPI 3 document
(drive by `drf-spectacular`). It covers **DRF endpoints only** — the Tastypie and
custom layers are not in it. It is public; no key required.

## 2. Authentication

Three distinct schemes. They are easy to confuse because two of them use a
header called `X-Api-Key` but validate against different stores.

### A. Personal API key — `apikey` parameter

- **Transport:** form field or query param named `apikey`.
- **Model:** `PersonalApiKey` (base64 of `id + salt + sha256(...)`).
- **Binding:** a key is minted for **one exact URL path**. The check is
  `key.endpoint === request.META['PATH_INFO']`, so a trailing slash mismatch fails.
- **Side effects on success:** the request is logged in as the key owner,
  `key.count`/`key.latest` are bumped, a `PersonApiKeyEvent` is written.
- **Freshness rule:** non-staff users must have logged into the GUI within
  `UTILS_APIKEY_GUI_LOGIN_LIMIT_DAYS` (30 days), else `400 Too long since last regular login`.
- **Errors** (all `text/plain`):
  `405 Method not allowed`, `400 Missing apikey parameter`, `403 Invalid apikey`,
  `400 Apikey endpoint mismatch`, `400 Too long since last regular login`,
  `400 Bad or missing parameters`.

Valid key endpoints (`PERSON_API_KEY_VALUES`, **no trailing slash**):

```
/api/iesg/position                       /api/notify/meeting/registration
/api/v2/person/person                    /api/notify/meeting/bluesheet
/api/meeting/session/video/url           /api/notify/session/attendees
/api/meeting/session/recording-name      /api/notify/session/chatlog
/api/appauth/authortools                 /api/notify/session/polls
/api/appauth/bibxml
```

Role checks (`@role_required`) are layered on top _after_ the key logs the user
in. Missing role → `403 Restricted to role: X` (or `roles: A, B`).

### B. App API token — `X-Api-Key` header

- **Transport:** `X-Api-Key: <token>`.
- **Model:** `AppApiToken`, stored as HMAC-SHA384 with `APP_API_TOKEN_PEPPER_BYTES`.
  Alternatively `settings.APP_API_TOKENS = { "<endpoint>": ["<raw token>", ...] }`.
- **Binding:** a symbolic endpoint name, normally `"<module>.<viewname>"`, e.g.
  `ietf.api.views.draft_aliases`. Each endpoint gets its own tokens, so a single
  capability can be revoked independently.
- **Failure:** `403` with an **empty body**.
- **Caching:** the token store is cached for 24h. Revoking a DB token can lag up
  to a day _unless_ it is done via the Django admin, which force-refreshes the cache.

```ts
const res = await fetch('https://datatracker.ietf.org/api/person/email/', {
  headers: { 'X-Api-Key': process.env.DATATRACKER_API_TOKEN! }
});
if (res.status === 403) throw new Error('bad or missing API token');
const { addresses } = (await res.json()) as { addresses: string[] };
```

### C. DRF token — `X-Api-Key` header, per-view endpoint

DRF adds `ietf.api.authentication.ApiKeyAuthentication` (puts the raw header
value in `request.auth`, does **not** validate) plus `HasApiKey` permission,
which calls the same `is_valid_token()` against `view.api_key_endpoint`.

Two consequences worth knowing:

- `SessionAuthentication` is configured but **useless**: `HasApiKey` returns
  `false` when no token is presented, so a logged-in browser session cannot call
  DRF endpoints.
- Any view without an `api_key_endpoint` is unreachable (permission returns
  `false`). This includes the generated API root at `GET /api/purple/`, which
  therefore always 403s.

DRF `api_key_endpoint` values in use:

```
ietf.api.meeting.session.video_url        ietf.api.red_api
ietf.api.meeting.session.recording_name   ietf.api.reef_api
ietf.api.meeting.session.bluesheet        ietf.person.api_uuid
ietf.api.meeting.session.attendees        ietf.person.api_uuid_by_pk
ietf.api.meeting.session.chatlog          ietf.api.views_rpc
ietf.api.meeting.session.polls
ietf.api.meeting.registration.attended
ietf.api.meeting.registration.attended_by_uuid
ietf.ietfauth.api_migration.verify
ietf.ietfauth.api_migration.claim_email
```

> Note the migration endpoints use **underscored** names
> (`ietf.ietfauth.api_migration.verify`) that differ from their hyphenated Django
> URL names (`ietf.api.migration_api.verify`). Tokens are bound to the former.

### D. OIDC

`/api/openid/` is a standard OpenID Connect provider
(`OIDC_USERINFO = ietf.ietfauth.utils.openid_userinfo`). Use it if you want
user-delegated access rather than a service token.

## 3. Cross-cutting conventions

**DRF layer**

- Request and response are `application/json` only. Any other `Content-Type`
  gets `415`, except `POST /api/purple/rfc/publish/files/` which is
  `multipart/form-data`.
- Errors use `drf-standardized-errors`:
  ```json
  {
    "errors": [
      {
        "code": "required",
        "detail": "This field is required.",
        "attr": "title"
      }
    ]
  }
  ```
- `202 Accepted` + empty body for fire-and-forget jobs.

**Tastypie layer**

- List: `{"objects": [...], "meta": {"limit", "offset", "total_count", "next", "previous"}}`
- Detail: the object itself.
- Multi-get (`/set/<id>;<id>/`): `{"objects": [...], "not_found": [...]}`.
- Every object carries `"resource_uri"`. Related objects serialize to URI
  strings (or `null` / `[]`).
- Datetimes are UTC, rendered `2021-05-01T12:00:00Z`.
- Format via `?format=json|xml|yaml|jsonp` or `Accept`; JSONP via `?callback=`.

**Custom layer** — no single convention. Families use `text/plain` messages,
`{"error", "messages"}`, `{status, title, detail}`, `{"result", "reason"}`, or
plain `{"addresses": [...]}`. Each endpoint below states its own shape.

**Global**

- **No throttling anywhere.** Not at the app layer, not in nginx.
- **CORS:** `CORS_ORIGIN_ALLOW_ALL = True` for GET on `/api/*` — any origin may read.
- **Pagination:** `limit`/`offset` with a `{count, next, previous, results}`
  envelope on DRF list endpoints that opt in; `limit`/`offset`/`order_by` on Tastypie.
- **State-changing custom endpoints are `csrf_exempt`**, so plain `POST` works
  from a script. Exception: `/api/group/role-holder-addresses/` is not exempt.

```sh
DATATRACKER_BASE_URL=https://datatracker.ietf.org
DATATRACKER_API_TOKEN=...        # scheme B / C: X-Api-Key
DATATRACKER_APIKEY=...           # scheme A: apikey parameter
```

## 5. Things that will bite you

1. **Token-gated endpoints are duplicated by the public v1 API.**
   `GET /api/person/email/` requires an app token and returns active addresses.
   `GET /api/v1/person/email/?active=true` needs **no auth** and returns
   `Email.objects.all()` with `address`, `time`, `active`, `person`, plus
   pagination. Likewise `/api/person/email/<email>/related/` is reproducible as
   `/api/v1/person/email/?person__email__address=<email>`, and
   `/api/group/role-holder-addresses/` as `/api/v1/group/role/`.
   Use whichever you like, but do not assume the token-gated one is private.

2. **`/api/submission/` accepts uploads with no authentication.** The `user`
   field is free text naming the submitter account. Rate limits are keyed on
   `remote_ip`, which is read from `CF-Connecting-IP` / `X-Forwarded-For`
   (first hop) — i.e. client-spoofable.

3. **`POST /api/directauth/` always returns HTTP 200.** Success or failure is
   only visible in the JSON body: `{"result": "success"}` vs
   `{"result": "failure", "reason": "..."}`. Always inspect the body.

4. **Personal API keys are path-exact.** A key for `/api/notify/meeting/bluesheet`
   will not work for `/api/notify/meeting/bluesheet/`. Watch the slash.

5. **Renaming a view revokes its tokens**, because endpoint names are derived
   from Python module paths.

6. **`/api/person/uuid/by-person-pk/` is deprecated** (marked as such in the
   OpenAPI schema). Prefer UUID-keyed lookups.
